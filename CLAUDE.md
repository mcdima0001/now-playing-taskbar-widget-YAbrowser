# CLAUDE.md

Форк [Priler/now-playing-taskbar-widget](https://github.com/Priler/now-playing-taskbar-widget).
Добавлена поддержка браузеров, которые не публикуют трек в системную медиасессию
Windows (SMTC), и несколько правок поведения под личное использование.

## Зачем форк

Яндекс.Браузер не создаёт SMTC-сессию вообще: он проигрывает звук собственным
`YandexMediaPlayer` мимо чемиумовского `SystemMediaControlsNotifier`. Проверено на
Windows 11 и Яндекс.Браузере 26.8: строка `Windows.Media.SystemMediaTransportControls`
в `browser.dll` есть, фича `HardwareMediaKeyHandling` включена принудительно, но
сессия не появляется — при том что Edge на той же машине её создаёт. Настройками
это не лечится, поэтому данные берутся из вкладки расширением.

## Из чего состоит

| Файл | Роль |
|---|---|
| `bridge-extension/` | Расширение MV3: читает `navigator.mediaSession` и вёрстку плеера, шлёт состояние в виджет |
| `BrowserBridge.cs` | WebSocket-сервер виджета на `127.0.0.1:45219`, принимает только `Origin: chrome-extension://` |
| `MediaHub.cs` | Общий источник: системная сессия плюс браузер под интерфейсом `MediaService` |
| `SourceActivator.cs` | Клик по названию показывает приложение-источник, найденное по AUMID из SMTC |

Окно (`MainWindow.xaml.cs`) о браузере не знает: у него поменялся только тип поля
`_media` с `MediaService` на `MediaHub`.

## Грабли, на которые уже наступили

- **WebSocket написан вручную** поверх `TcpListener`. `HttpListener` потребовал бы
  `netsh urlacl` или прав администратора, а виджет работает от обычного пользователя.
- **Расширение ставится распакованным**, поэтому после правок его нужно обновлять
  кнопкой в `browser://extensions`. Версия уходит в каждом сообщении (поле `v`) —
  по логу видно, какая реально запущена.
- **У Яндекс Музыки две раскладки плеера** одновременно: `VibePlayerBar*` и
  `PlayerBarDesktopWithBackgroundProgressBar*`. Кнопки ищутся внутри найденного
  плеербара, иначе цепляются одноимённые кнопки треков в списках.
- **Пометка explicit**: контейнер `Meta_explicitMarkContainer` отрисован всегда,
  даже когда пометки нет. Признак — только сам `svg` с классом `ExplicitMarkIcon`.
- **Панель задач Windows 11 нарисована на XAML**, классические `WinEvent` для её
  кнопок не приходят. Позиция Пуска и погоды отслеживается опросом UIA раз в 200 мс
  с кешированием ссылок на элементы.
- **Окно прозрачное** (`AllowsTransparency`), поэтому WPF рисует его процессором:
  каждая перерисовка ~4 мс. Непрерывная анимация полосы прогресса на 60 кадрах
  стоила 24% ядра — сейчас шаг 200 мс и движение масштабом, а не шириной.
- **В кнопке погоды лежат обе карточки сразу** - показанная и следующая
  («32°C Sunny» с правым краем 107 и «Temps to rise» со 154), на одной высоте и
  обе с `IsOffscreen=False`. По геометрии не различить; видимую выдаёт имя самой
  кнопки («Погода 32°C Sunny»), по нему и отбираются тексты. Пока брали максимум,
  виджет вставал по невидимой карточке и слева зияла дыра в полсотни пикселей.
- **Браузер душит таймеры в замолчавшей фоновой вкладке**: на паузе `setInterval`
  в content.js срабатывает раз в минуту (замерено: 3-4 с до паузы, 60 с после).
  Поэтому состояние тянет service worker опросом раз в 4 с - доставку сообщений
  throttling не трогает - а виджет держит паузу, пока жив сокет, а не по таймауту.
- **Замеры расхода** делать только в установившемся режиме: первые ~40 секунд после
  запуска уходят на JIT и прогрев, и цифры завышены в разы.

## Сборка

```
dotnet publish SpotifyTaskbarWidget.csproj -c Release -o out
```

Нужен .NET SDK 8 и Windows: WPF на Linux не собирается.

## Установщик и релизы

`setup.iss` собирает Inno Setup 6 в один exe: виджет, расширение рядом в
`bridge-extension` и автозагрузка .NET 8, если его нет. Ставится в профиль
пользователя (`PrivilegesRequired=lowest`), UAC не спрашивает.

Выпуск: `git tag vX.Y.Z && git push fork vX.Y.Z`. Дальше `.github/workflows/release.yml`
собирает на windows-раннере и сам прикладывает exe к релизу; пуш в `main`
собирает то же самое в артефакты, чтобы поломка была видна сразу.

Грабли установщика:

- **`{app}` в `InitializeWizard` ещё не раскрыт** — обращение к нему валит
  установщик молча. Тексты страниц ставить в `CurPageChanged`.
- **Никакого `taskkill` в `[UninstallRun]`**: удаление одной копии убивало
  работающий виджет пользователя. Закрытие делает Restart Manager
  (`CloseApplications=yes`).
